Codex桌面端反复要求重新登录

本文记录一次 Codex 桌面端登录循环问题的实际排查过程。症状是：应用空闲时看起来正常，但打开历史会话、开始新的文字对话，甚至从语音对话切换到文字输入后，应用就要求重新登录。

2026-08-22

一、问题表现

2026 年 8 月下旬，我的 Windows Codex 桌面端开始出现登录循环：

  • 打开桌面端后保持空闲，应用不会立刻报错；
  • 修改设置、下载插件等操作基本正常；
  • 打开历史会话后，过几秒钟被切回登录界面；
  • 新建文字对话并运行几秒后，再次要求登录；
  • 语音对话可以正常进行，但结束语音后开始输入文字，又会触发登录；
  • 重新登录只能暂时恢复，之后仍会重复出现。

这类现象很容易被误判为账号过期、代理不稳定或本地会话文件损坏。实际排查后，问题并不在这些地方。

二、我的环境与对照结果

当时使用的版本如下：

项目 版本或状态
操作系统 Windows 11
About Codex 显示的桌面客户端版本 26.818.41509
Microsoft Store AppX 包版本 26.818.5229.0
Codex CLI 0.149.0
登录方式 Sign in with ChatGPT

这里需要特别说明两个桌面版本号：26.818.41509 是应用 About 页面显示的客户端版本，26.818.5229.0 是 Windows 中注册的 Microsoft Store AppX 包版本。它们属于同一个安装的不同版本标识，并不矛盾。

几个对照结果很关键：

  • ChatGPT 网页版可以正常使用；
  • Codex CLI 使用同一个账号可以正常执行任务；
  • 桌面端的设置页面和插件下载并不是一开始就失败；
  • 清理或重新生成本地认证状态、重置应用和重装同一版本，都不能从根本上解决问题。

如果账号、网络和 CLI 都正常，而只有桌面端在特定操作后退出登录，问题更可能位于桌面端自己的认证桥接逻辑，而不是账号本身。

三、从 GitHub issue 找到共同特征

在 openai/codex 的 issue 中，我找到了多份几乎相同的报告。

这些报告的共同特征包括：

  1. 登录流程表面上成功，桌面端也能短暂显示已登录状态；
  2. 打开历史会话、发送消息或任务接近完成时，桌面端请求账号设置接口；
  3. 该接口返回 HTTP 401；
  4. 客户端把这个局部接口错误当成整个 ChatGPT 会话失效；
  5. 内存中的 access token 被清空，日志出现 auth_token_missing；
  6. 后续请求不再附带 token，界面回到登录页。

关键请求通常类似于：

1

GET /backend-api/accounts/{account_id}/settings

部分个人账号会收到：

1

401 Must use workspace account for this operation

也有报告记录到：

1

401 Missing valid access token or actor biscuit

问题在于，这个 401 更像是“当前账号不适用某个 workspace-only 功能”的局部权限错误，而不是“整个 OAuth 登录已失效”。但 26.818 系列桌面端的通用认证处理逻辑没有正确区分这两种情况，导致有效会话被错误清除。

四、最终有效的解决方法：清理浏览器中的 OAuth 会话

我亲自验证成功的方法，是清理默认浏览器中与 ChatGPT 登录相关的站点数据，然后重新完成一次登录。

1. 完全退出 Codex

先关闭 Codex 桌面端。为了避免旧进程继续使用旧的认证状态，最好确认应用已经完全退出，而不是只关闭窗口。

2. 清理相关网站数据

在 Chrome 中打开网站数据管理页面。不同版本的 Chrome 界面名称可能略有差异，通常可以从以下路径进入：

1

设置 → 隐私和安全 → 第三方 Cookie → 查看所有网站数据和权限

分别搜索并删除以下站点的数据：

  • chatgpt.com
  • auth.openai.com
  • openai.com

这里建议只删除上述 OpenAI/ChatGPT 相关站点的数据，不要直接清空整个浏览器的所有 Cookie、密码和浏览记录。

3. 只登录准备使用的账号

清理完成后，在浏览器中只登录准备给 Codex 使用的 ChatGPT 账号。如果浏览器中登录过多个 ChatGPT 账号，先退出其他账号，避免 OAuth 登录流程继承错误的多账号会话状态。

4. 重新登录 Codex

重新打开 Codex。应用要求登录时，按照正常流程在浏览器中完成授权。登录结束后，依次验证：

  • 打开一个已有历史会话；
  • 新建一个文字对话并发送消息；
  • 等待完整回复结束；
  • 如果平时使用语音，再测试结束语音后切换到文字输入。

我的结果是：登录循环停止，历史会话和新的文字对话都恢复正常，不需要再次重置应用或重装软件。

5. 不想影响主浏览器时的替代做法

如果不希望清理日常使用的默认浏览器，可以暂时隔离 OAuth 会话：

  1. 将一个不常用的浏览器临时设置为系统默认浏览器；
  2. 在这个临时默认浏览器中清理 chatgpt.com、auth.openai.com 和 openai.com 的站点数据；
  3. 只登录准备给 Codex 使用的 ChatGPT 账号；
  4. 重新打开 Codex；
  5. 当 Codex 要求重新登录时，让 OAuth 流程在这个临时默认浏览器中完成；
  6. 登录成功后，确认 Codex 能够打开历史会话并发送文字消息；
  7. 确认恢复正常后，再把默认浏览器切回原来的浏览器。

这个方法的本质是隔离 OAuth 浏览器会话，避免影响主浏览器中其他网站的登录状态。它是一个降低影响范围的 workaround，不保证适用于所有账号和所有版本。

五、其他方案与证据等级

Codex CLI：本机可用

在这次排查中，Codex CLI 0.149.0 使用同一账号可以正常执行任务。这说明账号凭据和基础网络链路并没有整体失效。

如果桌面端暂时无法使用，可以先用 CLI 作为临时替代，但它不能修复桌面端本身的问题。

回退到 26.810：社区报告有效，未在本文中亲自验证

多个 issue 报告称，回退到 26.810 系列后，打开历史会话不再触发登录循环。Windows issue 中有用户提到 26.810.7004.0，其他平台也有类似的 26.810 回退结果。

这个方案需要注意：

  • 它是社区报告的临时 workaround，不是本文作者的亲自验证结果；
  • 自动更新可能会把应用重新升级到出现问题的版本；
  • 长期停留在旧版本可能错过安全更新和功能更新。

因此，除非浏览器会话清理无效且必须立即使用桌面端，否则不建议把回退当作长期方案。

重装和重置：对这个问题通常无效

相关 issue 中，多名用户已经尝试过：

  • 删除并重新生成认证文件；
  • 修改凭据存储方式；
  • Windows App Repair/Reset；
  • 卸载、重启、重新安装；
  • 清理应用缓存和本地状态。

这些方法可能清理本地状态，但无法改变 26.818 桌面端对特定 401 响应的错误处理逻辑，所以通常不能解决根因。

六、官方修复状态

截至 2026 年 8 月 22 日，相关 issue 仍主要处于公开报告和复现阶段：

  • #39189、#39850、#39925、#40074 等相关 issue 仍是 Open；
  • 没有看到维护者确认该登录循环已经修复；
  • 没有看到明确对应 Windows 桌面端 26.819 的发布说明；
  • Codex 仓库中的部分 workspace 相关改动，主要针对 apps/plugins 功能，不能直接视为本次桌面认证循环的修复。

所以目前更准确的说法是：问题已经被多个用户稳定复现，根因方向也较明确，但当时还没有一个得到官方确认的桌面端修复版本。

七、排查这类问题时可以先看什么

以后如果再次遇到类似问题，可以先用下面的现象快速判断方向：

现象 更可能的方向
网页版、CLI 和移动端都无法登录 账号、服务或网络问题
只有桌面端要求重新登录 桌面端认证桥接或本地会话问题
空闲正常，打开会话后退出 会话恢复/账号设置请求触发问题
语音正常，文字消息触发退出 不同功能路径的认证处理差异
重装后仍然在相同操作点退出 更像版本回归，而不是本地文件损坏
日志出现 desktop_fetch_auth_401、auth_token_missing 重点检查桌面端如何处理 401 和 token 刷新

最重要的一点是：不要看到“要求重新登录”就立刻认定账号失效。 如果同一账号在网页版和 CLI 中都正常，应该进一步确认究竟是登录流程失败，还是桌面端在某个后续请求中错误地丢弃了有效会话。

八、总结

这次问题表面上是“Codex 桌面端登录失效”，实际表现更接近：

  1. 26.818 桌面端在个人账号上访问了 workspace 相关接口；
  2. 该接口返回局部 401；
  3. 客户端把局部权限错误误判成全局 token 失效；
  4. 桌面端丢弃有效认证状态，进入登录循环；
  5. 清理浏览器中的旧 OAuth 会话并只登录目标账号后，桌面端恢复正常。

对遇到相同问题的用户，建议按这个顺序处理：

  1. 先确认网页版和 Codex CLI 是否正常；
  2. 完全退出桌面端；
  3. 只清理 OpenAI/ChatGPT 相关站点数据；
  4. 只登录准备使用的 ChatGPT 账号；
  5. 重新完成桌面端登录并测试历史会话、文字消息和语音切换；
  6. 如果不想影响主浏览器，使用临时默认浏览器隔离 OAuth 会话；
  7. 仍然无效时，再考虑 CLI 或社区报告的旧版本回退方案。

这次排查也说明，复现步骤和对照测试比反复重装更有价值：当一个功能路径能正常工作、另一个路径稳定触发退出时，问题往往隐藏在两条路径之间的认证状态处理差异中。
